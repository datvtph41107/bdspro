# BDSPro — Product discovery and requirements
2026-11-25. RQ-01 OPEN. No customer segment, buyer, production user, SLA or first workflow confirmed by this document.

The product owner must clarify which real-estate job is worth solving, for whom, who pays/approves, what evidence exists and what the team can deliver/support. Read [RQ-01](RQ-01-product-and-first-workflow.md), [legacy and current evidence](SOURCE_BASELINE.md) and [requirement review](REQUIREMENT_REVIEW.md). The repository is evidence of implemented or intended behavior, not validated product demand. The old multi-service and v4 snapshots are discovery inputs, not a migration backlog. Existing contracts remain intact until a scoped decision is approved.

Decision authority: business/product decision maker (to be identified) confirms market, rules and scope; actual prospective users validate workflow and acceptance; backend owner owns technical choices, security, testing, delivery and operations; frontend owner validates UX/API use and failure states; AI analyzes, challenges and assists, never acts as stakeholder or certifies production outcomes. No invented independent reviewer or user interviews.

Use one active case, a concise record and a reviewable PR. For a small team, these are not separate departments or mandatory ceremonies. See [engineering charter](../architecture/engineering-charter.md).
