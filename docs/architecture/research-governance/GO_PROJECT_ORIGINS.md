## Decision proposal
DEV-START-01 PROPOSED: database-first small increments for IND-01 because PostgreSQL/sqlc/go-migrate fixed and data invariants are concrete; then one vertical HTTP workflow, with tests at each useful step. Use standard net/http ServeMux as candidate first HTTP adapter (method patterns Go1.22+), direct pgx/sqlc dependency wiring, no mandatory CLI/log manager/DI/Redis/custom context before relevant requirement; safety requirements still apply before exposure. Existing code preserved. No workspace/branch/reset or migration execution yet. Prefer SimpleBank as primary learning sequence and gobank as contrast, Gogs ancestry for evolution, PocketBase/Miniflux as counterexamples to inference from first public commit. Not a demand to copy any project.
Reference docs: https://docs.sqlc.dev/en/latest/tutorials/getting-started-postgresql.html ; https://github.com/golang-migrate/migrate/blob/master/GETTING_STARTED.md ; https://pkg.go.dev/github.com/jackc/pgx/v5/pgxpool ; https://go.dev/blog/routing-enhancements ; https://pkg.go.dev/net/http ; https://go.dev/doc/tutorial/add-a-test . Read just relevant API, try in IDE, run and explain actual outputs, then review. User writes runtime, generated code normal. Suggested initial sequence after S3/S4 approval: migration/constraint in disposable database -> sqlc query/generated types -> Go connection/read-write/test -> secure registration -> login/session -> /me/logout/negative checks -> local ops. No real user exposure until security/recovery/operational gate.
