# Architecture implementation status

**Reviewed source:** `refactor/explicit-routes-cmd-20261026` based on `dev` via the earlier architecture checkpoint.

## Implemented in source
- `cmd/bdspro/main.go` contains explicit process start, dependency creation and cleanup.
- `db/open.go` opens/pings PostgreSQL and applies migrations.
- `app/http/server/` owns only engine configuration, CORS and HTTP listener.
- `routes/` registers actual Gin handlers (no `Handlers` registry or binding table).
- `app/http/controllers/` parses its own typed Body/Query input once, then invokes services.
- `app/http/request/` is the single small parser using Gin methods directly, not a request-context object store.
- `app/http/middleware/` contains named authentication, IP/source admission, denial monitor, request logging, and body size guard.
- SQL is defined under `db/query/`, generated by SQLC; PostgreSQL owner is SQLStore.
- `worker/` executes queue functions and `jobs/` executes the verify-email action.
- `app/errors/`, `app/http/responses/`, `app/http/resources/` remain independent owners.

## Explicit limits
- Existing test and integration suites were removed at the user's direction. This reduces evidence of behavior parity.
- CI now checks migrations, compilation, Compose, HTTP smoke, static checks and source ownership; these are **not** equivalent to comprehensive unit/integration regression coverage.
- Service/Store transaction separation is not fully completed; Phone OTP commit-on-invalid-code must retain existing data behavior.
- No Admin route or generic cache/pagination/filter module was introduced without a real runtime consumer.
- Re-check response/error compatibility and Google/OTP behavior on a disposable local environment before deploying.

See `docs/architecture/http.md` and `docs/architecture/workflow.md`.
