# Persistence: schema, SQLC and transaction ownership

The **only canonical schema history** is `db/migration/*.sql`.
`db/query/*.sql` defines named queries; `sqlc.yaml` generates Go code into
`models/db/sqlc/`. The generated Go is committed and compared in CI.

`models/db/store_init.go` connects to PostgreSQL, pings it, and closes a
failed pool. `models/db/store.go` owns the SQLStore runtime and ExecTx transaction boundary.
`cmd/migrate.go` and development-mode `cmd/web.go` call the same versioned
SQL migration implementation using database settings loaded from INI.
`make migrateup` uses the same selected INI as `make server`.

A GORM introduction would be a *different* implementation decision:
which operations justify it, who owns the transaction, and how it respects
the same schema migration owner. Running GORM AutoMigrate beside versioned
golang-migrate is prohibited without an explicitly reviewed migration design.

A worker dispatches outbox work after records are committed, but PostgreSQL
and Redis do not share a transaction; delivery is at least once.
Do not claim exactly-once behavior from stable Asynq IDs alone.

## Generated SQLC, stable Store API

The only SQLC output is `models/db/sqlc/`. The companion `models/db/sqlc_types.gen.go`
is generated by `tools/dbalias` to preserve public `db.Account`, `db.Queries`,
`db.Store`, and existing model operations without handwritten wrappers.
Do not edit either generated output. `make generated` regenerates both;
`make sqlc-check` detects drift in CI.

`models/db/store.go` owns `Store` (consumer interface), `SQLStore` (pgx-backed
implementation), `NewStore`, and `ExecTx`. `models/db/store_init.go` opens
and checks PostgreSQL; runtime processes use `InitStore` and close it on shutdown.
A later transaction ownership review may relocate ExecTx to `context.go` without
introducing a second transaction implementation.

`models/db/list.go` implements query paging with a Gitea-style Paginator;
`TestPaginator` lives in `models/db/list_test.go`. Public callers must not
enable ListAll without explicit access and resource policies.

## Native SQLC output filenames

SQLC v1.30.0 generates the stable package in `models/db/sqlc/` using only
native naming flags from `sqlc.yaml`: `output_db_file_name`,
`output_models_file_name`, `output_querier_file_name`, and
`output_files_suffix: ".gen.go"`. Query files keep the SQL source basename:
`db/query/account.sql` generates `models/db/sqlc/account.sql.gen.go`.
This avoids any custom post-generation filename rewriting, while
`tools/dbalias` maintains the public `db.` type aliases automatically.
